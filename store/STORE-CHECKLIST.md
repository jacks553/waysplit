# Публикация Waysplit в Chrome Web Store — по шагам

Для того, кто заполняет панель магазина впервые. Шаги — как в SPEC-STORE.md, раздел 4: кто делает, что нажать, что куда вставить. Названия кнопок даны по документации магазина (по-английски); в русском интерфейсе панели они переведены — ищите по смыслу. **Если в панели что-то не так, как здесь написано, остановитесь и напишите мне** — разберёмся по актуальной документации.

Всё для магазина лежит в папке `store/`:

| Файл | Что в нём |
|---|---|
| `waysplit-1.0.0.zip` | архив расширения для загрузки (собирается командой ниже, в git не хранится) |
| `listing-ru.md` | тексты карточки: описание, категория, язык, ссылки, какие картинки куда |
| `privacy-tab.md` | вкладка «Конфиденциальность»: назначение, обоснования разрешений, данные, ссылка на политику |
| `test-instructions.md` | заметки для проверяющих |
| `icon-128.png`, `screenshots/1…5-*.png`, `promo-440x280.png` | картинки |

Панель разработчика: https://chrome.google.com/webstore/devconsole (вход тем аккаунтом Google, на котором зарегистрирован разработчик).

> **Состояние (12 ноября 2026 г.):** Waysplit 1.0.0 прошёл проверку магазина и опубликован с видимостью «По ссылке» (Unlisted): https://chromewebstore.google.com/detail/waysplit/fdgapnefknckjikbklcanoklhnmcgklg. Шаги 2–5 сделаны; дальше — проверка по шагу 6 и решение, переключать ли на «Для всех».

## Шаг 2 (вы): загрузить архив и узнать ID — на проверку не отправлять

**Сделано 9 ноября 2026 г.** ID элемента в магазине — `fdgapnefknckjikbklcanoklhnmcgklg`. Как это делалось:

1. В папке проекта соберите архив:
   ```powershell
   powershell -ExecutionPolicy Bypass -File tools\build-store.ps1
   ```
   В конце должно быть «Готово: …\store\waysplit-1.0.0.zip». (Имя на GitHub — `jacks553` — уже вписано в ссылки, поэтому `-Draft` больше не нужен.)
2. В панели нажмите **Add new item** («Добавить новый элемент»).
3. **Choose file** → выберите `store\waysplit-1.0.0.zip` → **Upload**. Если архив и manifest в порядке, откроется страница нового элемента.
4. Скопируйте **ID элемента** — 32 строчные латинские буквы. Он виден на странице элемента и в адресной строке панели (…/devconsole/…/**ID**/edit).
5. Больше ничего не заполняйте и **не нажимайте Submit for review**. Элемент останется черновиком.
6. Пришлите мне ID из магазина.

Служебный адрес почты GitHub присылать не понадобилось: он складывается из открытого номера учётной записи и имени — `67103658+jacks553@users.noreply.github.com` (тот же адрес виден в GitHub → Settings → Emails под галочкой «Keep my email addresses private»). Им подписан коммит публичного репозитория; ваша настоящая почта туда не попала.

## Шаг 4 (вместе): репозиторий, выпуск, страница политики

1. **Вы (сделано):** на GitHub → **New repository** → имя `waysplit`, **Public**, без README, .gitignore и лицензии (они уже есть) → **Create repository**.
2. **Я:** готовлю публичную копию одной командой — `cd tools; go run ./release public -author "jacks553 <67103658+jacks553@users.noreply.github.com>"`. Она берёт последний коммит без внутренних заметок (PROGRESS.md, SPEC*.md), ищет во всех файлах ваши секреты и похожее на них и создаёт **новый** репозиторий с историей из одного коммита — старых коммитов (в них эти заметки и ваша прежняя почта) в нём нет. Автор коммита — ваше имя на GitHub и служебный адрес. **Следующие обновления** — та же команда с `-message "что изменилось"`: `dist\public` уже клон публичного репозитория, поэтому изменения ложатся новым коммитом поверх его истории и отправляются обычным `git push` (без перезаписи); перед коммитом команда печатает, какие файлы меняются.
3. **Я:** из папки `dist\public` отправляю на GitHub (если GitHub попросит войти — откроется окно входа, подтвердите):
   ```powershell
   git remote add origin https://github.com/jacks553/waysplit.git
   git push -u origin main
   ```
4. **Вы:** в репозитории → **Settings** → **Pages** → Source: **Deploy from a branch** → Branch: **main**, папка **/docs** → **Save**. Через пару минут откройте `https://jacks553.github.io/waysplit/privacy.html` — должна открыться политика конфиденциальности.
5. **Я: выпуск собирается сам по тегу.** Там же, в `dist\public`:
   ```powershell
   git tag v1.0.0
   git push origin v1.0.0
   ```
   На вкладке **Actions** появится запуск «Выпуск» (около 15 минут): тесты, ядра sing-box и Xray из официальных выпусков (со сверкой SHA-256), сборка, установка компаньона из собранного архива, проверка в Chrome на распакованном архиве расширения, исходный код ядер. Если всё зелёное — в **Releases** появится «Waysplit 1.0.0»: `Waysplit-companion.zip`, `Waysplit-extension.zip` (расширение для ручной установки), их SHA-256, два архива исходного кода ядер (`…-source.tar.gz`), список изменений из `CHANGELOG.md` и инструкция «Как попробовать до магазина». Если запуск красный, выпуск не создастся — причина видна заметкой у запуска.
6. **Я** проверяю: обе постоянные ссылки (`https://github.com/jacks553/waysplit/releases/latest/download/Waysplit-companion.zip` и `…/Waysplit-extension.zip`) скачивают архивы, а их SHA-256 совпадают с опубликованными на странице выпуска.

### Друзьям: магазин и ручная установка

**До одобрения** Waysplit ставили вручную из выпуска на GitHub (раздел README «Как попробовать до магазина»). **Теперь (12 ноября 2026 г.)** расширение опубликовано в магазине «по ссылке», и README переделан: в начале — две ссылки (расширение из магазина и компаньон с GitHub), «Как установить» — компаньон, расширение из магазина, ссылка или подписка; ручная установка — «Ручная установка (запасной вариант)» для тех, у кого магазин недоступен; кто ставил вручную — «Переход с ручной версии на версию из магазина» (резервная копия → версия из магазина → удалить ручную → восстановить из копии; компаньон переустанавливать не нужно). Эти же три раздела `tools\ci.ps1` кладёт в описание следующих выпусков; описание выпуска 1.0.0 исправлено вручную (Edit release).

## День публикации (вы): архив компаньона — на проверку в Microsoft

Как только в Releases появился выпуск (шаг 4), отправьте архив компаньона в Microsoft как его разработчик. Антивирусы иногда по ошибке считают опасными новые неподписанные программы и ядра VPN; файл, который Microsoft проверила и признала чистым, встроенный антивирус Windows (Microsoft Defender) потом не трогает. Бесплатно, минут 10. **Если в форме что-то не так, как здесь написано, — остановитесь и напишите мне.**

1. Скачайте `Waysplit-companion.zip` кнопкой «Скачать» и сверьте `Get-FileHash` с SHA-256 на странице выпуска: отправлять нужно именно этот файл.
2. Откройте https://www.microsoft.com/en-us/wdsi/filesubmission и войдите учётной записью Microsoft.
3. Кто вы — разработчик программы (**Software developer**); продукт — **Microsoft Defender Antivirus** (для Windows 10 и 11).
4. Загрузите `Waysplit-companion.zip`. На вопрос, что это за файл, — **Incorrectly detected as malware/malicious** (ложное срабатывание; так и выбирают, даже если пока ничего не обнаружено).
5. В поле для дополнительных сведений вставьте:
   ```
   Companion app for the Waysplit Chrome extension (open source, Apache-2.0): https://github.com/jacks553/waysplit
   The archive contains our program waysplit-host.exe, an installer script and the unmodified official
   releases of the sing-box and Xray-core VPN cores (versions and sources: CORES.txt in the archive).
   Release page: https://github.com/jacks553/waysplit/releases/latest
   ```
6. Отправьте. Ответ придёт на почту учётной записи — обычно за несколько дней. Перешлите его мне; если какой-то файл всё-таки сочтут опасным, разберёмся.

Предупреждение SmartScreen («Система Windows защитила ваш компьютер») это не уберёт: доверие SmartScreen программа набирает со временем, по числу скачиваний без жалоб, или цифровой подписью — к этому вернёмся после публикации.

## Шаг 6: после одобрения — проверка (SPEC-STORE.md, раздел 6)

Перед проверкой: в обычном профиле Chrome **выключите версию для разработки** (chrome://extensions → выключатель у распакованного Waysplit) — две версии в одном профиле спорят за прокси. Удобнее проверять в новом профиле Chrome (меню профиля → «Добавить»): там чисто.

- [x] **Магазин принял архив** без `key` и без лишних файлов — проверка пройдена, расширение опубликовано «по ссылке» (12 ноября 2026 г.).
- [ ] **Компаньон из выпуска ставится двойным щелчком и без интернета.** Скачайте архив со страницы выпуска в «Загрузки», «Извлечь всё…», отключите интернет (Wi-Fi или кабель) и запустите «Установить.cmd» (через SmartScreen: «Подробнее» → «Выполнить в любом случае»). Go и права администратора не нужны. В конце — «Готово», в окне — версии компаньона, sing-box и Xray. Интернет потом включите обратно.
- [ ] **Версия из магазина в чистом профиле находит компаньон и подключается.** В новом профиле откройте ссылку на карточку (https://chromewebstore.google.com/detail/waysplit/fdgapnefknckjikbklcanoklhnmcgklg), установите, на «Начале работы» — «Проверить ещё раз» → «Компаньон на связи: 1.0.0…». Вставьте свою ссылку, «Включить VPN», откройте https://api.ipify.org — IP сервера.
- [ ] **Ручная копия заменена версией из магазина** — у себя и у друзей: две копии в одном Chrome спорят за прокси. Порядок — README, «Переход с ручной версии на версию из магазина».
- [ ] **Версия для разработки тоже работает** (компаньон пускает оба ID): в обычном профиле включите её обратно (а версию из магазина там не ставьте или выключите) — подключается как раньше.
- [ ] **«Удалить.cmd» убирает регистрацию и файлы**: запустите его из `%LOCALAPPDATA%\Programs\Waysplit`. Он спросит про идентификатор устройства — **просто нажмите Enter** (оставить): тогда провайдер после переустановки увидит тот же компьютер. Проверьте: папки `%LOCALAPPDATA%\Programs\Waysplit` нет, в `%LOCALAPPDATA%\Waysplit` остался только файл `device-id`, окно расширения пишет «Компаньон не установлен» с шагами установки. Потом поставьте компаньон обратно («Установить.cmd»). Ответ «да» удаляет и идентификатор — его на своём компьютере не проверяйте: провайдер посчитает компьютер новым устройством.
- [ ] **Страница политики конфиденциальности открывается** по ссылке из карточки магазина.
- [ ] **Нигде нет ваших ссылок, IP, ключей и почты** — ни на скриншотах (вымышленные данные), ни в репозитории и его истории (проверка `release public` из шага 4 и один коммит со служебным адресом).
- [ ] **Этот файл понятен** — если где-то споткнулись, скажите, поправлю.

Потом вы решаете, переключать ли видимость на **Public** («Для всех»): Distribution → Visibility → Public → отправить. Помните: **каждая новая загрузка в магазин — с увеличенной версией** в manifest.json и снова проходит проверку.
