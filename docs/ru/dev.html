Waysplit для разработчиков

Как устроен Waysplit, как собрать его из исходников и чей код в нём работает.

Как это устроено

  1. Расширение лежит в папке extension/. Это окно с вкладками, страница "Начало работы" и фоновая часть. Окно описано в extension/popup/. Одна и та же страница служит окном на панели, развёрнутой вкладкой и страницей настроек. Расширение говорит Chrome, какой сайт куда направлять. Для этого служит PAC-скрипт.
  2. Компаньон лежит в папке host/. Это программа waysplit-host.exe на Go. Chrome сам запускает её и общается с ней через native messaging. Компаньон разбирает ссылки, скачивает подписки, собирает настройки ядер, запускает и останавливает ядра.
  3. Ядро sing-box открывает на компьютере локальные прокси на адресе 127.0.0.1 и шифрует трафик до сервера.
  4. Ядро Xray нужно только для того, чего нет в sing-box. Это серверы с транспортом XHTTP и шифрованием VLESS Encryption. Компаньон сам решает по ссылке, каким ядром запускать сервер. Xray он запускает, только когда нужен его сервер. В списке у таких серверов стоит пометка "Xray".
Chrome ──▶ прокси 127.0.0.1:<порт сервера> ──▶ sing-box или Xray ──VLESS / Hysteria2──▶ VPN-сервер ──▶ сайт

Установка из исходников

Понадобятся 64-битная Windows 10 или 11, Google Chrome 120 или новее и Go. Go ставится командой winget install -e --id GoLang.Go. Права администратора не нужны.

  1. Положите папку проекта туда, где она будет лежать постоянно. Chrome берёт распакованное расширение прямо из неё.
  2. Выполните в терминале в папке проекта: 
    powershell -ExecutionPolicy Bypass -File tools\setup.ps1

    Скрипт кладёт в host\bin ядра sing-box и Xray тех же версий, что получают пользователи. Версии записаны в tools\cores.json. Ядра, которые уже лежат с верной SHA-256, скрипт не трогает. Остальные он скачивает из официальных выпусков и сверяет SHA-256 архива и каждого файла. Потом он собирает host\bin\waysplit-host.exe и регистрирует его в Chrome командой install. Она кладёт файл в %LOCALAPPDATA%\Waysplit и пишет ключ реестра текущего пользователя. Скрипт можно запускать сколько угодно раз.

  3. Откройте chrome://extensions и включите "Режим разработчика". Нажмите "Загрузить распакованное расширение" и выберите папку extension. ID расширения будет jckofomkflegkkhaaccmjbjjhoielnli. Его задаёт поле key в manifest.json.

Зарегистрировать компаньон вручную можно командой host\bin\waysplit-host.exe install, убрать регистрацию можно командой uninstall. Если вы перенесли папку проекта, выполните install ещё раз. Компаньон пускает два ID расширения: для разработки и из магазина. ID магазина записан в host/storeid.go. Поэтому обе версии работают с одним компаньоном. Не включайте их одновременно, иначе они будут спорить за прокси Chrome.

Журналы и конфиги лежат в %LOCALAPPDATA%\Waysplit\. В host.log пишет компаньон, секретов в этом журнале нет. В sing-box.log и xray.log пишут ядра. В config.json и xray.json есть секреты, их никому не отправляйте.

Сборка и тесты

cd host; go build -o bin\waysplit-host.exe .; go test ./...; cd ..
cd tools; go test ./...; cd ..
npm test
node tools/chrome-check.js

go test ./... в папке host проверяет разбор ссылок и подписок и сборку конфигов обоих ядер. Конфиги сравниваются с эталонами и прогоняются через sing-box check и xray run -test. Ещё проверяются запуск и остановка ядер, сквозные подключения через локальные тестовые серверы, протокол связи с Chrome и регистрация в реестре. Регистрация проверяется во временном ключе. Интернет для этих тестов не нужен.

npm test проверяет код расширения, для него нужен Node.js. node tools/chrome-check.js проверяет расширение в настоящем Chrome без окна, с временным профилем. Для этой проверки нужен интернет, через него идут пинг и "Мой IP". Компаньон должен быть собран и зарегистрирован, а порты 27101-27103 свободны.

Выпуск

Выпуск собирается сам. Поднимите версию в extension/manifest.json и host/main.go, допишите раздел в CHANGELOG.md, закоммитьте и отправьте тег:

git tag v1.2.3
git push origin v1.2.3

Тег запускает GitHub Actions по файлу .github/workflows/release.yml, а оттуда запускается tools/ci.ps1 -Sources. Скрипт сверяет версии тега, расширения и компаньона. Потом он гоняет все тесты: Go, npm test и проверку в Chrome. Проверка в Chrome идёт на распакованном Waysplit-extension.zip, то есть на том, что люди ставят вручную. Ядра скрипт скачивает из официальных выпусков и сверяет их SHA-256 с tools/cores.json. Затем он собирает архивы и проверяет установщик на собранном архиве во временной папке. Испорченный архив установщик не ставит, нормальный ставит без интернета, удаление проходит чисто. В конце скрипт скачивает архивы исходного кода ядер и создаёт выпуск. В выпуске лежат Waysplit-companion.zip, Waysplit-extension.zip, их SHA-256 и исходный код ядер. В Waysplit-extension.zip лежит расширение для ручной установки.

В описание выпуска попадают раздел версии из CHANGELOG.md и три раздела из README.md: "Как установить", "Ручная установка (запасной вариант)" и "Переход с ручной версии на версию из магазина". Ссылки в них должны быть полными, вида https://…. Относительные ссылки в описании выпуска не работают.

Архив для магазина лежит в файлах сборки на странице запуска в Actions под именем chrome-web-store-v1.2.3. В выпуск он не кладётся, чтобы пользователи не путали его с компаньоном. Тег с дефисом, например v1.2.3-rc1, даёт пробный выпуск. Последним такой выпуск не становится.

То же можно прогнать у себя командой powershell -ExecutionPolicy Bypass -File tools\ci.ps1 -Tag v1.2.3. Ядра берутся из host\bin или dist\cores, если их SHA-256 совпадает. Тогда интернет нужен только для проверки в Chrome. Пропустить её можно ключом -SkipChrome.

Собрать архивы вручную:

powershell -ExecutionPolicy Bypass -File tools\build-store.ps1       # store\waysplit-<версия>.zip
powershell -ExecutionPolicy Bypass -File tools\build-companion.ps1   # dist\Waysplit-companion.zip и .sha256
powershell -ExecutionPolicy Bypass -File tools\build-extension.ps1   # dist\Waysplit-extension.zip и .sha256

В архив для магазина попадает копия extension/ без поля key и без лишних файлов. Поле key магазин не принимает. Сборка проверяет manifest: описание на каждом языке должно быть не длиннее 132 символов. Ещё она проверяет значок 128: рисунок 96×96 и прозрачные поля по 16 пикселей. И проверяет, что в расширении нет кода из интернета.

В архиве компаньона лежат:

  • waysplit-host.exe;
  • ядра sing-box.exe и xray.exe из dist\cores;
  • установщик и инструкция;
  • LICENSE.txt и THIRD-PARTY-LICENSES.txt;
  • лицензии ядер;
  • CORES.txt;
  • SHA256SUMS.txt.

waysplit-host.exe собран с -trimpath, поэтому в нём нет путей этого компьютера. У него есть значок и сведения о версии, их видно в свойствах файла и в диспетчере задач. SHA-256 ядер сверяется с tools/cores.json. В THIRD-PARTY-LICENSES.txt лежат полные тексты лицензий всего чужого кода в exe. Список модулей для него берётся из go list -deps. Если у модуля нет файла лицензии, сборка останавливается. В CORES.txt записаны версии ядер, откуда они взяты и где их исходный код. По SHA256SUMS.txt установщик проверяет файлы.

Расширение для ручной установки собирается из extension/ как есть, с полем key. У распакованной копии тот же ID, что у версии для разработки, и компаньон её пускает. Сборка проверяет, что ID по key совпадает с host/extid.go. Ещё она проверяет, что в архиве нет ключей и служебных файлов.

Время файлов в архивах равно времени последнего коммита. Поэтому один и тот же код даёт один и тот же архив. Архив компаньона называется Waysplit-companion.zip, без версии в имени. Благодаря этому постоянная ссылка …/releases/latest/download/Waysplit-companion.zip всегда ведёт на последний выпуск. Каждая новая загрузка в магазин требует новой версии в manifest.json. Все шаги расписаны в store/STORE-CHECKLIST.md.

Скриншоты для магазина делает node tools/store-shots.js. Это настоящий интерфейс на вымышленных данных. Малую промо-картинку рисует cd tools; go run ./icons -promo ..\store\promo-440x280.png.

Публичный репозиторий собирает команда cd tools; go run ./release public [-author "Имя <ID+имя@users.noreply.github.com>"] [-message "что изменилось"]. Она выгружает последний коммит в dist\public без внутренних заметок и проверяет все файлы на секреты. Коммит делается от служебного адреса GitHub. В первый раз получается новый репозиторий из одного коммита. Дальше dist\public работает как клон публичного репозитория. Файлы в нём заменяются, а история остаётся. Изменения ложатся новым коммитом поверх неё, для этого нужен -message. Список изменений команда печатает. Отправляются они обычным git push.

Постоянный ID расширения

ID задаётся полем key в extension/manifest.json. Ключ делает tools/genkey. Это ключ RSA-2048, его открытая часть записана в key. ID записан в host/extid.go. Это первые 32 hex-символа SHA-256 от ключа, в которых цифры 0-f заменены буквами a-p. Приватный ключ лежит в tools\genkey\private-key.pem и в git не попадает.

Команда cd tools; go run ./genkey; cd .. просто перепишет файлы, если ключ уже есть. ID при этом не меняется.

Команда go run ./genkey -new делает новый ключ, и ID поменяется. После этого пересоберите компаньон, выполните install и перезагрузите расширение в Chrome.

Проверка ссылки без браузера

  1. Создайте в папке проекта файл links.local.txt. В git он не попадает. Вставьте туда ссылку vless://… или hysteria2://…. Можно несколько, по одной на строку, и адрес подписки https://…. Строки, которые начинаются с #, считаются комментариями.
  2. Запустите нужную команду из папки проекта:
КомандаЧто делает
host\bin\waysplit-host.exe parseпоказывает, какие серверы распознаны, а какие пропущены и почему. У серверов Xray стоит пометка [Xray]
host\bin\waysplit-host.exe configсобирает конфиги sing-box и Xray, проверяет их ядрами и показывает, какой сервер на каком порту
host\bin\waysplit-host.exe tryзапускает ядра, проверяет пинг и IP через каждый сервер и держит прокси, пока не нажмёте Enter
host\bin\waysplit-host.exe subinfo файлделает то же, что кнопка "Проверить" у подписки, и выдаёт отчёт без секретов. Адрес подписки берётся из файла или пишется прямо в команде. Файлы *.local.txt в git не попадают. С -device подписка проверяется ещё и с идентификатором устройства, и провайдер может засчитать устройство. С -proxy 27101 проверка идёт через сервер в работающем ядре

parse, config и try скачивают подписки так же, как расширение. Идентификатор устройства они отправляют, только если без него серверов нет. Флаг -device отправляет его сразу. Флаг -port N задаёт первый локальный порт.

Прокси можно проверить командой curl.exe -x socks5h://127.0.0.1:27101 https://api.ipify.org. Она должна показать IP сервера. В Windows PowerShell под именем curl скрывается другая команда, поэтому пишите curl.exe.
