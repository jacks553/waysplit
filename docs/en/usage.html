How to use Waysplit

Everything is controlled from the extension popup. It opens with the Waysplit icon on the Chrome toolbar. At the bottom of the popup there are four tabs: Home, Servers, Rules and Settings. The popup always opens on Home. The server picker, adding servers, subscription details and diagnostics open as separate screens on top of a tab. To go back, use the round key at the top left or the Esc key. The "Open in a tab" button at the top right opens the same interface in a full browser tab. The "?" button menu has "Help" and "Report a problem". To its left is the language button: RU or EN.

The popup looks like a push-button phone. Everything you read and set up is on the greenish screen. The tab keys are under the screen. On Home there is also a round power key with a lamp under the screen.

The popup has two designs: new and classic. The new one is the default, and this page describes it. The classic one looks like the popup of version 1.2.1. Servers, rules and settings are shared by both. The classic design shows flags instead of country codes, and its rules have site icons. The icons come only from Chrome's own memory, with no requests to the internet. You switch the design in the menu that opens when you click the Waysplit name in the popup header. The popup opens in the other design at once. The same menu changes the theme. The same choices are in the settings: Settings, Appearance.

Messages at the bottom of the popup behave in different ways. Short success messages disappear by themselves. Errors stay until you close them with the cross or the Esc key. Messages with a reason or an instruction stay too, for example "skipped…" or "reload the tab".

If you have no servers yet, paste a vless://… or hysteria2://… link or a subscription URL on Home and click "Add". You can paste several links, one per line. Later you add servers on the "Servers" tab with the "+ Add" button. The first server you add becomes the current one.

The round key under the screen on Home turns the VPN on and off for all sites. The screen shows the state in large letters: "VPN is on" or "VPN is off". When the VPN is on, all Chrome traffic goes through the current server. Sites with "without VPN" rules are the exception.

A lamp with a label is lit to the left of the key. Green means the VPN is on. Yellow means the VPN is off but rules are working. Red means an error. The screen then shows a short name of the problem in large letters, for example "No response", "No companion" or "Port in use". The line below gives the reason and what to do.

The top row of the screen shows the current server: signal bars, the name and the latency. Click the row to open the server picker. It has a search by name and address. Favorite servers come first, marked with a star. Then come the groups by subscription and your own servers. In the lists a two-letter country code stands before the server name, for example NL or DE. It comes from the flag in the server name.

Four bars mean a latency under 600 ms, three under 1 s, two under 1.6 s, one means more. Dimmed bars mean the server did not respond. The server row then says so: "no response". Hover to see the milliseconds and the reason. The ping of visible servers refreshes automatically, at most once a minute. Click a server to make it current. Sites switch to it in a second or two, and you do not need to restart the browser.

The "Servers" tab holds subscriptions and your own servers. It has the "Ping all" and "Fastest" buttons. Click a row to choose a server. The "⋯" menu of each server has ping, rename, copy link, favorites, move up or down, and delete. You can also change the order by dragging. Ping works when the VPN is off too: the core starts for the time of the check.

If you close Chrome with the VPN on, the VPN turns on automatically at the next start. You can turn this off in the settings.

Subscriptions

A subscription URL https://… goes into the same field as server links. Waysplit downloads the server list and shows the subscription name, traffic and expiry date. After that it updates the subscription automatically. By default this happens every 12 hours, but the subscription server can set its own interval.

The list is downloaded with the User-Agent v2rayN/7.0. With a browser User-Agent, panels like Marzban and Remnawave return a web page instead of the list. You can change the User-Agent in the settings.

On update, servers are recognized by address and key. So the chosen server and the site rules stay in place, and favorites are not lost. If the subscription cannot be downloaded directly while the VPN is on, it is downloaded through the VPN.

Subscriptions are on the "Servers" tab. Click a subscription to open its details. The "⋯" menu of a subscription has "Update", "Details and check", "Rename" and "Delete". Deleting removes the subscription together with its servers.

If the panel sent a message from the provider, you see it in the subscription block.

Waysplit does not decrypt a subscription encrypted for the Happ app. Links to such subscriptions start with happ://crypt…, and only the Happ app can open them. Pasting such a link is useless, Waysplit will suggest asking the provider for a regular one. Get a regular subscription link https://… in your provider account or ask support for it. A link like happ://add/https://… works as is: Waysplit takes the URL from it.

Panels often give separate URLs for different apps. In Remnawave such URLs end with /json, /singbox, /mihomo and /clash. Any of them works. Waysplit understands a plain list of links, as text or in base64. It also understands Xray JSON, sing-box JSON and Clash or Mihomo YAML. From these it takes VLESS and Hysteria2 servers. The same server from several configs is added once. Servers of other protocols, for example VMess and Trojan, go to "skipped" with a reason. A link for classic Clash is usually empty, because it does not support VLESS. Waysplit says so.

If a subscription gives no servers or the wrong ones, open its details and click "Check subscription". Waysplit downloads it the way different apps do and shows a report. The report has the server response, the format, the number of servers of each kind and the headers. It has no subscription URL, server links or passwords. The report itself is in Russian for now. The "with the device ID" checkbox sends the ID of this computer to the provider. The provider may count it as one more device, so the checkbox is off by default.

Sites through VPN and without VPN

This site

Home has the "This site" block. It shows the domain of the open tab and an explanation. The explanation says which rule the site follows, or that there is no rule and the site goes like other sites. If the site has a subdomain, for example m.example.com, you can choose the level the rule applies to.

Two buttons, "Through VPN" and "Without VPN", show how the site opens now: the active one is filled. Clicking the other one creates or changes the rule for this domain. The button with a country code on the right opens the server picker for the site. Its first items are "Same as other sites" and "Without VPN". After "Remove rule" the site goes like other sites again.

Sometimes a rule cannot work right now: the VPN is off, and rules are disabled while the VPN is off. A framed warning says so. Its "Turn on rules" button turns on the setting "Rules work when VPN is off" at once. After any change click "Reload tab".

Site domains

Video, images and scripts of a site usually live on other domains. For youtube.com these are, for example, googlevideo.com and ytimg.com. So a rule for one domain is not enough. Site domains are attached to the rule. They follow the rule itself: the same action and the same server. They are a part of the rule, not separate rules. If you delete the rule, they go away with it.

The rule row shows how many site domains it has, for example "+6 site domains". The "⋯" menu of a rule has "Site domains…". It opens a list where you can remove any domain. A removed domain is not added again automatically. The same screen has the "Restore removed" button.

Site domains appear in two ways. The first way is ready-made sets. When you add a rule for the main domain of a set, the domains of the set are attached to it at once. The main domains of the sets are youtube.com, instagram.com, telegram.org, discord.com and chatgpt.com.

The second way: Waysplit collects them on its own while the site is open. Only "through VPN" rules work this way. Domains that the tab with the site contacts are added to its rule. Home then shows a hint that new site domains were found and the tab needs a reload. This needs the Chrome permission to see tab requests. Waysplit asks for it once, after the first "through VPN" rule, and explains why it is needed. Without the permission only the sets work. You can turn automatic adding off in the settings with the "Add site domains automatically" checkbox.

Domains are not added from incognito tabs, even if you allowed the extension to work there. Rules are stored on disk, and nothing from incognito should stay there.

Chrome chooses the proxy by the request address, not by the tab. So an attached domain follows the rule in all tabs. To keep half the internet from going through the VPN of one site, some domains are not added by themselves:

  • common services: google.com, gstatic.com, analytics, ads, script libraries like jsdelivr.net;
  • domains in the ru, рф and su zones and sites from the "Russian sites without VPN" set;
  • domains that have their own rule;
  • local addresses.

If you need such a common domain through the VPN, add a regular rule for it. For shared hostings like cloudfront.net and github.io only the full name is added, for example d123.cloudfront.net, not the whole hosting. Both lists are in extension/lib/domain-sets.json, in the common and hostings sections.

Russian sites without VPN

On Home this is a row with a checkbox. The same checkbox is in the settings and on the "Getting started" page. It is off by default. When it is on, the .ru, .рф and .su zones and Russian services on other domains open without VPN even when the VPN is on. These are VK, Odnoklassniki, Yandex, Wildberries, Avito and others. Their list is in the "Russian sites without VPN" set in extension/lib/domain-sets.json. The setting exists because some Russian sites and banks do not let in visitors from foreign IPs.

It is a setting, not a set of rules. Nothing appears in the rule list, only a reminder line on the "Rules" tab. Your rules and site domains take priority. A "through VPN" rule for a single Russian site works even when the setting is on. For such a site the "This site" block says "Without VPN: Russian site".

Domains of this tab

This link is in the "This site" block. It opens a separate screen with the list of sites the tab contacted. Check the ones you need. At the bottom you choose the action, and the "Add rules" button adds separate rules for them. It helps when you need to add rules by hand. It needs the same permission to see tab requests. If the list is empty, click "Reload tab" on the same screen. Waysplit reloads the tab and reads the list again.

The "Rules" tab

The "Enter a domain" field both adds rules and searches the list. Next to it you choose what to do with the site: "Without VPN", "Through VPN" like other sites, or a specific server. Then click "+". You can paste several domains or page addresses, one per line.

A rule row has the domain, the direction label and the trash bin. The label shows where the site goes: "without VPN", "VPN" or a country code with the server name. Click the label to open the server picker. The trash bin deletes the rule at once. The message at the bottom of the popup then has an "Undo" button. It brings the rule back as it was, with its site domains. The "⋯" menu of a row has "Disable rule" and "Site domains…". A disabled rule stays in the list.

The "⋯" menu of the tab itself has the ready-made sets, rule import and export, and the "Rules work when VPN is off" checkbox. The sets are in the file extension/lib/domain-sets.json. The export file holds rules together with their site domains and has no secrets. Files for import and export are chosen on the page opened in a tab.

How rules work

A rule for a domain also covers all its subdomains. The most specific rule wins. For example, google.com goes through the VPN, and mail.google.com has a "without VPN" rule. Then mail goes without VPN. You can also set a rule for a whole zone: ru, рф or su.

When the VPN is on, everything goes through the current server, except sites with rules. When the VPN is off, everything goes without VPN, but "through VPN" rules keep working. You can turn this off with the "Rules work when VPN is off" checkbox. It is on the "Settings" tab and in the "⋯" menu on the "Rules" tab. Local addresses like localhost and 192.168.x.x always go without VPN.

Protection, settings, diagnostics

While the VPN is on, WebRTC protection works. Sites cannot learn your real IP through WebRTC. When you turn the VPN off, everything goes back to how it was. You can turn the protection off in the settings.

The "Settings" tab holds:

  • what to do if the server is unavailable;
  • WebRTC protection;
  • rules while the VPN is off;
  • Russian sites without VPN;
  • adding site domains automatically;
  • connecting when Chrome starts;
  • the User-Agent and the update interval for subscriptions;
  • the start of the local port range;
  • the log level;
  • the design, the theme and the language.

If the server is unavailable, you can choose "Don't open the site" or "Open without VPN". The first option protects from leaks. The language can be the same as in Chrome, Russian or English. It changes at once and applies to both designs and to the "Getting started" page.

The theme can be dark, light or the same as the system. The quickest way to change it is the menu that opens when you click the Waysplit name in the header. Each design has its own theme. The new design starts with the dark one. The theme changes the color of the body, and the screen stays greenish. The classic design starts with "same as system". The "Getting started" page uses the theme of the new design.

At the bottom of the tab there are "Diagnostics", "Help", "Report a problem" and the versions of the extension, the companion and the cores.

A backup is made with the "Save backup" button. One file gets servers, subscriptions, rules with site domains, favorites and settings. The file is saved and chosen on the page opened in a tab. The file holds secrets: server links and subscription URLs. Keep it like a password. The "Restore from backup" button replaces the current data.

Diagnostics shows the versions of the extension, the companion and the cores, the extension ID and the state of the cores. It also shows who controls the proxy and whether WebRTC protection works. It has the "My current IP" button, events and logs without secrets. The "Copy debug report" button is there too.
