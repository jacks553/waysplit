Waysplit for developers

How Waysplit works, how to build it from source and whose code runs inside it.

How it works

  1. The extension is in the extension/ folder. It has the popup with tabs, the "Getting started" page and the background part. The popup has two designs. The new one is in extension/popup/, the classic one in extension/classic/. The classic design repeats the popup of version 1.2.1 and is frozen. The same page serves as the toolbar popup, the page opened in a tab and the options page. The extension tells Chrome which site goes where. A PAC script does that.
  2. The companion is in the host/ folder. It is the program waysplit-host.exe, written in Go. Chrome starts it and talks to it over native messaging. The companion parses links, downloads subscriptions, builds core configs, starts and stops the cores.
  3. The sing-box core opens local proxies on 127.0.0.1 and encrypts traffic to the server.
  4. The Xray core is needed only for what sing-box lacks. These are servers with the XHTTP transport and VLESS Encryption. The companion decides by the link which core runs a server. It starts Xray only when one of its servers is needed. Such servers are marked "Xray" in the list.
Chrome ──▶ proxy 127.0.0.1:<server port> ──▶ sing-box or Xray ──VLESS / Hysteria2──▶ VPN server ──▶ site

Setting up from source

You need 64-bit Windows 10 or 11, Google Chrome 120 or later and Go. Install Go with winget install -e --id GoLang.Go. Administrator rights are not needed.

  1. Put the project folder where it will stay. Chrome loads the unpacked extension right from it.
  2. Run in a terminal in the project folder: 
    powershell -ExecutionPolicy Bypass -File tools\setup.ps1

    The script puts the sing-box and Xray cores into host\bin, the same versions that users get. The versions are listed in tools\cores.json. Cores that are already there with the right SHA-256 are left alone. The script downloads the rest from the official releases and checks the SHA-256 of the archive and of every file. Then it builds host\bin\waysplit-host.exe and registers it in Chrome with the install command. That command puts a file into %LOCALAPPDATA%\Waysplit and writes a registry key of the current user. You can run the script as many times as you like.

  3. Open chrome://extensions and turn on "Developer mode". Click "Load unpacked" and choose the extension folder. The extension ID will be jckofomkflegkkhaaccmjbjjhoielnli. The key field in manifest.json sets it.

To register the companion by hand, run host\bin\waysplit-host.exe install. To unregister it, run uninstall. If you move the project folder, run install again. The companion accepts two extension IDs: the development one and the store one. The store ID is in host/storeid.go. So both versions work with one companion. Do not enable them at the same time, or they will fight over the Chrome proxy.

Logs and configs are in %LOCALAPPDATA%\Waysplit\. The companion writes host.log, and this log has no secrets. The cores write sing-box.log and xray.log. config.json and xray.json hold secrets, do not send them to anyone.

Build and tests

cd host; go build -o bin\waysplit-host.exe .; go test ./...; cd ..
cd tools; go test ./...; cd ..
npm test
node tools/chrome-check.js

go test ./... in the host folder checks the parsing of links and subscriptions and the config building for both cores. The configs are compared with reference files and run through sing-box check and xray run -test. It also checks starting and stopping the cores, end-to-end connections through local test servers, the protocol for talking to Chrome and the registry registration. The registration is checked in a temporary key. These tests do not need the internet.

npm test checks the extension code and needs Node.js. node tools/chrome-check.js checks the extension in a real headless Chrome with a temporary profile. This check needs the internet for the ping and "My current IP". The companion must be built and registered, and ports 27101-27103 must be free.

Release

A release builds itself. Raise the version in extension/manifest.json and host/main.go, add a section to CHANGELOG.md, commit and push a tag:

git tag v1.2.3
git push origin v1.2.3

The tag starts GitHub Actions by the file .github/workflows/release.yml, which runs tools/ci.ps1 -Sources. The script compares the versions of the tag, the extension and the companion. Then it runs all tests: Go, npm test and the Chrome check. The Chrome check runs on the unpacked Waysplit-extension.zip, the very thing people install by hand. The script downloads the cores from the official releases and checks their SHA-256 against tools/cores.json. Next it builds the archives and checks the installer on the built archive in a temporary folder. The installer refuses a damaged archive, installs a good one without the internet, and uninstalls cleanly. At the end the script downloads the source archives of the cores and creates the release. The release holds Waysplit-companion.zip, Waysplit-extension.zip, their SHA-256 and the core source code. Waysplit-extension.zip holds the extension for a manual install.

The release notes get the version section from CHANGELOG.md and three sections from README.md: "Как установить", "Ручная установка (запасной вариант)" and "Переход с ручной версии на версию из магазина". Links in them must be full, like https://…. Relative links do not work in release notes.

The store archive is among the build files on the run page in Actions, under the name chrome-web-store-v1.2.3. It is not put into the release, so users do not confuse it with the companion. A tag with a hyphen, for example v1.2.3-rc1, makes a pre-release. Such a release does not become the latest one.

You can run the same on your computer with powershell -ExecutionPolicy Bypass -File tools\ci.ps1 -Tag v1.2.3. The cores are taken from host\bin or dist\cores if their SHA-256 matches. Then the internet is needed only for the Chrome check. Skip it with the -SkipChrome switch.

To build the archives by hand:

powershell -ExecutionPolicy Bypass -File tools\build-store.ps1       # store\waysplit-<version>.zip
powershell -ExecutionPolicy Bypass -File tools\build-companion.ps1   # dist\Waysplit-companion.zip and .sha256
powershell -ExecutionPolicy Bypass -File tools\build-extension.ps1   # dist\Waysplit-extension.zip and .sha256

The store archive gets a copy of extension/ without the key field and without extra files. The store does not accept the key field. The build checks the manifest: the description in every language must be no longer than 132 characters. It also checks the 128 icon: a 96×96 picture with transparent margins of 16 pixels. And it checks that the extension has no code from the internet.

The companion archive holds:

  • waysplit-host.exe;
  • the cores sing-box.exe and xray.exe from dist\cores;
  • the installer and the instructions;
  • LICENSE.txt and THIRD-PARTY-LICENSES.txt;
  • the core licenses;
  • CORES.txt;
  • SHA256SUMS.txt.

waysplit-host.exe is built with -trimpath, so it has no paths of this computer. It has an icon and version info, visible in the file properties and in Task Manager. The SHA-256 of the cores is checked against tools/cores.json. THIRD-PARTY-LICENSES.txt holds the full license texts of all third-party code in the exe. The module list for it comes from go list -deps. If a module has no license file, the build stops. CORES.txt lists the core versions, where they come from and where their source code is. The installer checks the files by SHA256SUMS.txt.

The extension for a manual install is built from extension/ as is, with the key field. An unpacked copy has the same ID as the development version, and the companion accepts it. The build checks that the ID from key matches host/extid.go. It also checks that the archive has no keys or service files.

File times in the archives equal the time of the last commit. So the same code gives the same archive. The companion archive is named Waysplit-companion.zip, with no version in the name. Thanks to this the permanent link …/releases/latest/download/Waysplit-companion.zip always leads to the latest release. Every new upload to the store needs a new version in manifest.json. All steps are listed in store/STORE-CHECKLIST.md.

node tools/store-shots.js makes the store screenshots. They show the real interface on made-up data. cd tools; go run ./icons -promo ..\store\promo-440x280.png draws the small promo image.

The command cd tools; go run ./release public [-author "Name <ID+name@users.noreply.github.com>"] [-message "what changed"] builds the public repository. It exports the last commit to dist\public without internal notes and checks all files for secrets. The commit is made from a GitHub service address. The first run gives a new repository with one commit. After that dist\public works as a clone of the public repository. Files in it are replaced, and the history stays. Changes land as a new commit on top of it, which needs -message. The command prints the list of changes. You send them with a regular git push.

Permanent extension ID

The ID is set by the key field in extension/manifest.json. tools/genkey makes the key. It is an RSA-2048 key, and its public part is written in key. The ID is written in host/extid.go. It is the first 32 hex characters of the SHA-256 of the key, with digits 0-f replaced by letters a-p. The private key is in tools\genkey\private-key.pem and does not get into git.

The command cd tools; go run ./genkey; cd .. just rewrites the files if the key already exists. The ID does not change.

The command go run ./genkey -new makes a new key, and the ID changes. After that rebuild the companion, run install and reload the extension in Chrome.

Checking a link without the browser

  1. Create the file links.local.txt in the project folder. It does not get into git. Paste a vless://… or hysteria2://… link there. You can paste several, one per line, and a subscription URL https://…. Lines that start with # are comments.
  2. Run the command you need from the project folder:
CommandWhat it does
host\bin\waysplit-host.exe parseshows which servers are recognized and which are skipped and why. Xray servers are marked [Xray]
host\bin\waysplit-host.exe configbuilds the sing-box and Xray configs, checks them with the cores and shows which server is on which port
host\bin\waysplit-host.exe trystarts the cores, checks the ping and the IP through every server and keeps the proxies up until you press Enter
host\bin\waysplit-host.exe subinfo filedoes the same as the "Check subscription" button and prints a report without secrets. The subscription URL is taken from the file or written right in the command. *.local.txt files do not get into git

parse, config and try download subscriptions the same way the extension does. They send the device ID only if there are no servers without it. The -device flag sends it at once. The -port N flag sets the first local port. These commands print in Russian.

You can check a proxy with curl.exe -x socks5h://127.0.0.1:27101 https://api.ipify.org. It should show the IP of the server. In Windows PowerShell the name curl hides another command, so write curl.exe.
